# Fateweave — 개인용 사주 결혼운·궁합 분석 서비스 설계 명세서

- 작성일: 2026-10-25
- 상태: **설계 방향 승인(2026-10-25) — 구현은 실행 계획 검토 후 시작**
- 설계 방식: superpowers:brainstorming
- 권장 저장 위치(프로젝트 생성 시): `docs/superpowers/specs/2026-10-25-fateweave-design.md`

## 1. 목적 및 배경

청월당·헬로우봇의 유료 서비스 중 **개인 결혼사주**와 **커플 결혼운·궁합**에 해당하는 기능 범주를 공개된 명리학 규칙을 토대로 **독립 구현**한다. 개인이 이미 사용하는 Claude 일반 채팅에서 상세 리포트를 먼저 받고, 후속 질문으로 파고들 수 있어야 한다. 리포트는 Claude/ChatGPT 간에 재사용할 수 있어야 하며, 점괘의 길이보다 **출처 계산의 정확성, 검증 가능한 근거, 해석 간 일관성**을 중시한다.

서비스의 내용은 **전통 명리학 관법에 따른 풀이**로서 제공한다. 연애·결혼 사건이나 제3자의 의사를 과학적으로 예측하거나 확정한다는 의미로 제시하지 않는다.

## 2. 확정 요구사항 (대화에서 합의한 사항)

1. **대상 사용자:** 본인 1명. 회원가입/요금제/외부 고객 대상 공개 서비스는 불필요.
2. **개인 분석:** 성격·연애 성향·배우자상·결혼 적합성/결혼생활 성향·결혼 시기 및 대운·세운 흐름.
3. **커플 분석:** 남녀의 결혼 적합성, 결혼 성사운에 대한 전통적 인연 풀이, 양쪽 운 흐름을 고려한 결혼 시기 분석. 기존 `OX` 이분법 판정은 **폐기**.
4. **입력:** 생년월일과 출생시간(선택). 모르는 출생시간은 임의 추정하지 않고 시주 제외 및 해석 제약 명시.
5. **응답:** 웹툰·점수 시각화보다 텍스트형 **최초 심층 리포트 + 후속 AI 대화**.
6. **플랫폼:** Claude **일반 채팅**이 주 사용처; ChatGPT는 초기에는 구조화된 기준 리포트 전달. 두 AI의 직접 MCP 연결을 초기 완료 조건으로 잡지 않음.
7. **호스팅:** 운영 중인 OCI 인스턴스 재사용. 기존 서비스와 **별도 애플리케이션/프로세스**, 기존 PostgreSQL 인스턴스의 **전용 데이터베이스와 전용 권한** 사용.
8. **LLM 역할:** 확정적인 만세력 계산값은 서버에서 생성, 여러 명리 관법의 심층 해석은 Claude가 수행, 서버가 사전 정의된 검증을 수행.
9. **리포트:** 최초 해석을 **Canonical Report**로 저장. 대안 관법 해석은 허용하되 최초 문서를 조용히 덮어쓰지 않음. 오류 정정은 버전 추가로 처리.
10. **생성 방식:** Claude가 별도 유료 LLM API 호출 없이 리포트를 작성, **준비(prepare) → 해석(Claude) → 검증·확정(finalize)**의 2단계 MCP 흐름을 사용.
11. **해석 폭:** 십성, 배우자궁/배우자성, 합충형해, 격국·용신·조후, 대운·세운 등 복수 관법을 포괄하되 서로 다른 관법의 전제를 표시.

## 3. 목표 / 비목표 / 실패 조건

### 목표
- 동일 출생 입력에 대해 동일한 계산기 및 계산정책 버전이면 동일한 명식과 근거 데이터가 나온다.
- 개인/커플 각각 최초 Markdown 심층 리포트를 만든다.
- 서버 저장된 기준 리포트 및 계산 근거를 Claude가 재조회할 수 있다.
- ChatGPT에 기준 리포트를 전달했을 때 동일 계산·해석을 공유하고 추가 관법은 별도로 논의한다.
- 태어난 시간이 없으면 누락된 정보를 명시하고 분석 범위를 축소한다.
- 같은 OCI에서 기존 프로젝트와 분리하여 배포·재시작·백업한다.

### 비목표
- 청월당·헬로우봇의 비공개 내부 공식/문구/유료 화면을 그대로 복제.
- 유료 상품 접근 우회, 약관을 위반하는 비공개 데이터 수집.
- '결혼 가능 확률 82%'처럼 검증 근거가 없는 통계학적 확률 제공.
- 다중 사용자 계정, 소셜 로그인, 결제, 화려한 그래프, 모바일 웹 프런트엔드.
- 별도 OpenAI/Anthropic API를 통한 서버 측 LLM 자동 생성.
- Kafka, Redis, Elasticsearch, K8s 등 현재 개인용 규모에서 불필요한 구성.

### 실패 조건 (anti-goals)
- 서로 같은 출생정보인데 도구 호출 때마다 사주팔자·연도가 달라짐.
- 근거에 없는 원국·합충을 Claude가 임의로 만들어 정답처럼 제시.
- 저장되지 않은 보고서를 저장 완료했다고 안내.
- 근거 미검증 리포트가 최종본으로 확정되거나 원본을 덮어씀.
- 다른 서비스의 DB 또는 계정 정보가 원격 MCP를 통해 노출.

## 4. 검토한 접근 방식과 선택 근거

| 결정 지점 | 대안 | 선택 | 이유/트레이드오프 |
|---|---|---|---|
| 경험 | 웹 / 원격 MCP / 자체 AI 채팅 | **Claude 일반 채팅 + Remote MCP** | 추가 UI·별도 AI API 비용 최소화, 대신 Claude 도구 호출 제어는 불완전 |
| 공통 엔진 | 특정 클라이언트 결합 / 별도 API | **독립 Python 분석 계층 + MCP 어댑터** | 향후 다른 도구 연결 가능, 코드 구조는 약간 복잡 |
| 보고서 생성 | 서버 LLM API / Claude / 수동 | **Claude 생성** | 신규 사용료 회피, 도구 호출 누락·중단 상태에 대비 필요 |
| 저장 | 매번 재계산 / 결과 캐시 / 기준 리포트 | **불변 기준 리포트 + 버전** | 재사용과 감사 용이, 데이터 모델 추가 |
| 배포 | 기존 서비스 코드 통합 / 별도 서비스 / 별도 서버 | **OCI 동일 VM 내 독립 서비스 및 DB** | 비용 낮고 운영 격리, VM 자체 장애는 공유 |
| 검증 | LLM 자기 검증만 / 계산 근거 대조 / 전체 운명 예측 검증 | **결정론적 근거/형식 검증 + 해석 검토** | 정량 계산은 검증 가능, 최종 예언의 진위는 검증 불가 |

## 5. 사용자 여정

### 5.1 개인 결혼사주

1. Claude 일반 채팅에서: “양력 1998-xx-xx, 오후 2시, 남성의 결혼사주를 분석해줘.”
2. Claude가 MCP `prepare_analysis(mode="individual", profiles=[...])` 호출.
3. 서버가 명식·십성·대운·세운·관법별 근거 식별자(evidence ID)를 만들어 `analysis_id`와 함께 반환.
4. Claude가 정해진 보고서 구조로 최초 심층 리포트 작성. 모든 계산상 주장에 근거 ID 포함.
5. Claude가 `finalize_report(analysis_id, report)` 호출.
6. 서버가 검증 성공 시 불변 Canonical Report v1 저장하고 `report_id`, `version`, `status=FINALIZED` 반환.
7. Claude가 저장 성공 이후에만 사용자에게 “저장됨”을 안내. 실패 시 오류 근거를 보고 수정하여 재호출.
8. 사용자가 후속 질문하면 Claude가 `get_report` 및 필요 시 명식 데이터를 조회해서 답변.

### 5.2 커플 결혼운·궁합

1. 남녀 프로필 두 건을 `prepare_analysis(mode="couple", profiles=[personA,personB])`에 입력.
2. 개인 원국 계산 → 각자의 운 흐름 계산 → 상호관계 근거 구성.
3. Claude는 **결혼 적합성 / 결혼으로 이어지는 인연 해석 / 양쪽 결혼 시기**를 각각 심층 분석하고 상충 관법을 병기.
4. 동일한 검증·저장 절차 실행.
5. 대안 관법이 필요하면 `add_alternative_interpretation`으로 새로운 해석을 별도 추가. 기존 기준 리포트는 변경하지 않음.

### 5.3 ChatGPT에서 이어가기

- `get_report(report_id, format="markdown")`로 본문 + 근거 요약 + 버전 식별자가 포함된 내보내기 생성.
- 사용자가 ChatGPT 대화에 직접 전달. ChatGPT는 문서에 포함된 사실을 기준으로 후속 질문에 답한다.
- ChatGPT 채팅에서 발생한 새로운 대안 해석은 초기 MVP에서 자동 동기화하지 않음(이후 수동 반영/커넥터 고려).

## 6. 개념 아키텍처

```text
Claude 일반 채팅 (Remote MCP Connector)
       |
       | HTTPS / 인증
       v
OCI Nginx / TLS Reverse Proxy
       |
       v
MCP HTTP endpoint (FastAPI 기반 별도 서비스)
       |
       +-- Analysis Application Service
       |      +-- Manse Engine Adapter  (결정론적 명식·절기·대운)
       |      +-- Rule & Evidence Builder (십성·합충형해·관법 기초)
       |      +-- Report Validator (근거 ID · 값/연도/형식 대조)
       |
       +-- Report Repository
                 |
                 v
            PostgreSQL 전용 DB

Claude --> Markdown export --> ChatGPT (수동 전달, 초기 MVP)
```

- 코드 책임은 `domain`(원국·규칙), `application`(분석 생성·상태), `adapters/mcp`, `infra/db`로 분리 제안.
- 기존 Flight Friend 앱/DB와 소스, 계정 권한, 컨테이너/프로세스, 로그를 분리. 같은 VM의 CPU/메모리 장애 격리는 완전하지 않음.
- 배포 후보: Docker Compose의 독립 compose 프로젝트와 Nginx 경로 또는 서브도메인 라우팅. OCI 자원 용량·기존 배포 구조 확인 후 최종 확정.

## 7. 만세력·근거 엔진 정책

### 7.1 입력 규약

- 필수: 생년월일, 양력/음력 구분, 분석 관법이 필요로 하는 전통 성별 분류 또는 해당 해석법을 사용하는 여부.
- 선택: 출생 시간(알 수 없는 경우 NULL), 출생지 또는 타임존(기본값은 **제안: Asia/Seoul**, 사용자가 다른 곳에서 태어났으면 명시), 음력 윤달 여부.
- 출생시간이 없다면 시주를 계산·추정하지 않는다. 시주 의존 해석의 불확실성을 리포트에 표시한다.
- 자시(23시 전후), 입춘/절기 경계, 역사적 시간대/서머타임, 윤달 등은 **명시된 계산 정책**을 따라야 하며 같은 정책 버전에서 불변이어야 한다.

### 7.2 엔진 산출값

- 연·월·일·시주(알려진 범위), 음양/오행, 지장간, 십성, 12운성(지원 시), 합충형파해.
- 대운 시작 나이·순행/역행 판단에 필요한 규약, 대운과 세운.
- 관법별 evidence ID, 적용된 룰 ID 및 해석의 기초 사실.
- 결혼시기 후보 연도의 선정 여부는 후보 식별 과정과 전제 규칙을 명시. 예언적 사실처럼 표현 금지.
- 선택한 라이브러리와 만세력 정책의 버전을 `analysis_run`마다 기록.

### 7.3 복수 관법

십성/배우자성, 일지 배우자궁, 천간지지 합충형파해, 오행 균형, 격국·용신, 조후, 대운·세운을 해석 가능 관법으로 열어 둔다. 단, 특정 계산 요소가 미지원이거나 학파 차이로 해석 규칙이 확정되지 않았다면 **지원한 척하지 않고 생략 또는 '해석 관법상 의견'으로 표시**한다.

## 8. MCP 도구 계약 (안)

| Tool | 목적 | 핵심 입력 | 핵심 출력 |
|---|---|---|---|
| `prepare_analysis` | 분석 데이터와 근거 준비 | `mode`, `profiles`, optional `horizon_years` | `analysis_id`, `facts`, `evidence_catalog`, `missing_data`, `status=PREPARED` |
| `finalize_report` | 구조화된 초안을 검증·저장 | `analysis_id`, `sections`, `evidence_refs`, `idempotency_key` | 성공 시 `report_id`, `version`, `status=FINALIZED`; 실패 시 `validation_errors` |
| `get_report` | 기준 리포트 및 근거 조회·내보내기 | `report_id`, optional `version`, `format` | Markdown 또는 구조화 JSON, 버전 메타데이터 |
| `list_reports` | 과거 분석 선택 | optional `mode`, `limit` | 보고서 ID, 별칭, 생성일, 버전, 상태 |
| `add_alternative_interpretation` | 대안 해석 보존 | `report_id`, `school`, `content`, `evidence_refs` | 새 대안 해석 ID / 검증 결과 |

기본 보고서 스키마:

- 메타데이터: `analysis_id`, `report_type`, `report_version`, `manse_policy_version`, `rule_version`, `generated_by`, `generated_at`
- 공통: 분석 요약, 핵심 명식, 관법별 근거, 긍정·갈등/제약 요인, 종합 풀이, 대안 관법, 출생정보의 제약, 유의사항
- 개인: 성격/연애 성향, 배우자상, 결혼생활 성향, 연도별 결혼운 및 상세 판단 근거
- 커플: 결혼 적합성, 결혼 성사운이라는 전통적 인연 해석, 공통 유리 결혼 시기, 서로 다른 관법/상충 결론
- 각 근거 주장에는 서버가 발행한 `evidence_id`를 연결하고, 추론적 해석은 `interpretation`으로 구분.

## 9. 검증과 버전 정책

1. **스키마 검증:** 필수 섹션, 타입, 날짜 형식, 근거 ID 포맷 검사.
2. **근거 참조 검증:** 모든 참조 ID가 해당 analysis의 evidence catalog에 존재하는지 확인.
3. **결정론적 일치 검증:** 서술 중 구조화된 계산값(간지·십성·연도·대운 구간)이 스냅샷과 충돌하는지 검사. 자유서술 전체를 완벽하게 검증할 수 없으므로 계산상 중요한 주장은 구조화된 필드로 별도 제출하도록 설계.
4. **해석 주장 검토:** 같은 관법을 서로 모순되게 인용하는지 확인 가능한 범위만 검증. 예측의 참·거짓은 판정하지 못함.
5. **실패 처리:** `VALIDATION_FAILED` 상태 및 오류 반환. 원본 `analysis_id`는 보존, Claude가 수정본을 재제출. 최종 완료로 표시하지 않음.
6. **성공 처리:** 기준 리포트 v1 불변 저장; 동일 idempotency key의 재호출은 중복 저장 방지.
7. **정정:** 새로운 버전 v2 작성 시 이전 버전/정정 이유/수정 지점 유지. 이전 보고서를 조용히 덮어쓰지 않음.
8. **대안 해석:** 원본 리포트와 별도 저장. 해석이 상충한다면 관법과 근거를 나란히 보존.

분석 상태(안): `PREPARED → FINALIZED`, `PREPARED → VALIDATION_FAILED → FINALIZED`, `PREPARED → ABANDONED`. 보고서 버전은 별도 불변 레코드로 관리.

## 10. 데이터 모델 (논리 수준)

- `birth_profiles`: 개인 식별자(UUID), 별칭(선택), 출생정보, 출생시간 존재 여부, 입력 정책/타임존, 생성/갱신 정보.
- `analysis_runs`: 분석 ID, 유형(개인/커플), 참가자 IDs, 계산 스냅샷(JSONB), 계산·규칙 버전, 상태, 생성일.
- `report_versions`: 보고서 ID, analysis ID, version, 구조화 본문(JSONB), Markdown 본문, 생성 모델/프롬프트 버전, 검증 결과, 생성일, 불변 레코드.
- `alternative_interpretations`: 기준 보고서 ID 및 버전, 해석 관법, 근거 ID, 본문, 생성일.

외래키·유니크 제약: 한 `report_id + version`은 유일, `analysis_id + idempotency_key`는 중복 완료를 방지. 삭제 정책은 분석/프로필/대안 해석 관계를 확인하며 안전하게 연쇄 처리해야 함.

## 11. 보안·운영 정책

- Claude Cloud → OCI 공개 HTTPS MCP endpoint 연결. 프록시 뒤 애플리케이션 포트는 비공개로 둠.
- **개인용 인증 필수:** Claude 커스텀 커넥터의 고정 요청 헤더 API key/bearer token(지원되는 연결 환경에서), 별도 인증/권한 검사. 고정 토큰은 로그에 남기지 않고 회전 가능하게 관리. 플랫폼 변경 시 OAuth로 확장.
- **전용 DB/사용자:** 기존 서비스 DB 스키마 및 계정의 최소권한 분리. DB 외부 포트 비공개.
- 개인정보: 생년월일시·타인의 출생정보·연애 리포트는 민감하게 취급. 필수 데이터만 저장, 백업·저장 암호화 및 삭제 기능 제공. 로그에는 출생정보·리포트 본문을 기록하지 않음.
- 사용자 프로필 별칭 기반으로 결과 선택; 제3자의 실명 입력 불필요.
- 서비스 메트릭: MCP 요청수, 실패율, 검증 실패 사유, 분석 상태·응답 시간. 인적 출생정보 라벨 금지.
- OCI CPU/RAM/스토리지 예산, 기존 서비스 자원과 충돌 가능성 모니터링.
- DB 백업·복구 테스트, 토큰 유출 시 회전, 리포트/프로필 삭제 기능.

## 12. MVP 범위와 후속 진화

### MVP
- 양력·음력(윤달 포함 가능 여부는 라이브러리 검증 후 확정) 입력, 출생시간 선택.
- 개인/커플 분석용 명식 계산 및 상세 근거 생성.
- Claude Remote MCP 연결, 위 5개 도구(대안 해석 기능은 경량형 구현 허용).
- 복수 관법 리포트, 엄격한 정형 필드 검증, 불변 저장·조회, Markdown 복사/내보내기.
- OCI 독립 컨테이너/프로세스, PostgreSQL 별도 DB, HTTPS, 인증, 최소 백업.

### Post-MVP
- ChatGPT 직접 커넥터 연결 가능 시 MCP 어댑터 재사용.
- 기준 리포트의 수동/자동 교정 흐름, 관법별 테스트 케이스 축적.
- LLM 서버 API 생성 또는 여러 모델 비교(비용/재현성 필요 시).
- UI/시각화는 실제 필요가 생길 때만 추가.
- 해석 버전별 A/B 비교·일관성 평가와 근거 카탈로그 확장.

## 13. 검증 계획 / 인수 기준

- 알려진 참조 만세력 케이스와 동일한 연·월·일주 및 절기 경계 결과가 나온다.
- `time=null`이면 시주를 가정하지 않고 결과에 제약이 명시된다.
- 동일 입력 + 계산정책 버전 조합은 스냅샷 해시가 동일하다.
- 개인/커플 각각 `prepare_analysis` → Claude 보고서 → `finalize_report` → `get_report`의 실제 Claude 일반 채팅 종단간 경로를 통과한다.
- 잘못된 연도/일간/근거 ID를 포함한 제출이 거절되며 `FINALIZED`로 저장되지 않는다.
- 동일 요청 재시도로 보고서 중복 생성이 발생하지 않는다.
- `get_report(format="markdown")`를 ChatGPT에 전달한 뒤 기준 계산과 종합 결론을 식별할 수 있다.
- Claude 연결이 끊겨도 준비 상태는 남으며 확정되지 않은 결과를 '완료'로 표시하지 않는다.
- 타 서비스 DB 접근이나 인증 없는 보고서 조회가 차단된다.
- 기존 서비스 배포나 재시작과 관계없이 사주 서비스만 독립 배포·재시작 가능하다.

## 14. 남은 구현자 결정 — 설계 초안의 기본 제안

1. **만세력 라이브러리:** 정확성·라이선스·절기/시각 처리 테스트를 거쳐 Python 라이브러리 채택 또는 경계 조건 직접 보완(현 시점 미확정).
2. **원격 MCP:** MCP Python SDK / FastMCP 계열 + Streamable HTTP를 우선 검토. 실제 Claude 커넥터 등록·인증은 E2E 검증이 필요.
3. **생성 리포트 길이:** 깊고 풍부한 서술을 기본으로 하되 모델 한 번의 응답·도구 입력 제한을 고려해 섹션별 분할 제출 방식이 필요한지 기술 검증.
4. **개인정보 보존 기간:** 개인용이므로 명시적 삭제 시까지 보존하는 안을 제안하되, 사용자 승인 필요.
5. **기준 운세 관법:** 출생 성별·순역 대운·자시 정책 등 결과에 영향을 주는 관법별 선택값을 고정하고 버전 관리해야 함.
6. **프로필/커플 다건:** 향후 재조회와 비교를 위해 다건 저장을 권장(초기 기본값).
7. **Claude 호출 한계:** 채팅 클라이언트가 `finalize_report` 호출을 생략할 가능성은 서버에서 강제할 수 없다. 상태를 통해 완료 여부를 확인하고, 사용자에게 저장 도구 호출이 필요함을 명확히 안내.

## 16. Fateweave 실행 계획에서 고정하는 기술 기본값(제안)

- Python 3.12, 공식 MCP Python SDK 2.3.0 (`MCPServer`, Streamable HTTP), FastAPI, SQLAlchemy 2 async/asyncpg, Alembic, PostgreSQL.
- 만세력 후보 `korean-saju==0.3.0`(특히 절기/야자시/시간 미상의 모호성 테스트 필요), 음양력 변환 `korean-lunar-calendar==0.4.0`. 라이브러리 결과를 맹신하지 않고 경계 케이스 검증을 합격 조건으로 둠.
- 기본 관법: 한국식 야자시 분리 적용; 출생시간/출생 위치 미상 시 가정과 모호성을 드러냄.
- DB 내 기준 리포트와 그 버전은 불변, 관리용 삭제 도구는 외부 MCP에 노출하지 않음.
- 구조화된 계산 주장만 자동 검증을 보증하며 자유 문장 전체의 명리적 일관성은 완전히 기계 검증되지 않음.
- 원격 MCP 연결은 실제 Claude 계정의 기능 및 배포 환경에서 종단 간 확인해야 함.

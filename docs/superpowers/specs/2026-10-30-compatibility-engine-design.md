## 1. 정책 개정

| 기존 (MVP Task 5, rules-v1/v2) | 개정 (compat-score-v1) |
|---|---|
| 산술 궁합 점수를 만들지 않는다 | 결혼 적합성에 **설명 가능한 100점 지수**를 둔다. `score_type = "interpretive_index"` |
| 결혼 확률·퍼센트 금지 | **유지.** 지수는 확률이 아니다. "결혼 확률 N%"·"성사 확률"·O/X 표현은 계속 검증에서 거절한다 |
| — | 모든 점수는 서버가 결정론적으로 계산하고 Claude는 해석만 한다. Claude가 점수·연도를 바꿔 쓰면 검증에서 거절한다 |
| — | 정책 버전(`scoring_version`)을 분석 스냅샷과 리포트에 기록한다. 정책이 바뀌어도 과거 리포트는 불변이고 새 버전으로 생성한다 |

## 2. 세 층 분리: Fact → Assessment → Scoring

| 층 | 내용 | 위치 | 버전 |
|---|---|---|---|
| Fact | 두 명식에서 결정론적으로 성립하는 관계 (예: A 일지·B 일지 충) | `domain/couple.py`, `domain/tables.py` (기존) | `rules-vN` |
| Assessment | 그 관계가 궁합 영역에서 갖는 의미 (예: 배우자궁 긴장 요소) | `domain/compatibility/evaluator.py` (신규) | `compat-score-vN` |
| Scoring | 의미에 주는 가감점, 상한, 중복 방지 | `domain/compatibility/scoring.py`, `policies.py` (신규) | `compat-score-vN` |

- Fact evidence에는 점수를 넣지 않는다. 점수 evidence(`COMPAT_*`)는 어떤 Fact evidence ID에 몇 점을 줬는지 `contributions`로 참조한다.
- `source_ref`는 세 종류를 구분한다: `table:` (전통 관계표), `policy:compat-score-v1#<rule>` (Fateweave 배점 가정), `library:` (korean-saju 계산).

## 3. 현재 코드와의 대응

| 제안 | 현재 상태 | 할 일 |
|---|---|---|
| 두 명식 관계 Fact | 있음: `COUPLE_DAY_STEM`, `COUPLE_DAY_BRANCH`, `COUPLE_CROSS_PILLARS`, `COUPLE_DAY_STEM_ELEMENT`, `COUPLE_SPOUSE_STAR_MATCH`, `COUPLE_ELEMENT_COMPLEMENT`(A→B·B→A 방향 분리) | Fact는 유지. 점수화는 신규 패키지 |
| 개인 연도별 결혼 신호 | 있음: `domain/timing.py`의 단서(cue)·주의(caution)·순위 | 가중 점수(§6) 추가, 개인·커플 공용 |
| 공통 유리 시기 | 있음: `COUPLE_TIMING`(두 사람 모두 핵심 단서가 있는 해 우선) | **변경:** 모든 해에 순위를 매기지 않고 조건 충족 연도만 후보로. 없으면 "없음"을 반환(§6) |
| 출생시간 미상 처리 | 시주 관련 Fact 제외, `PARTIAL` + 대안 명식 | 점수 영역별 `UNAVAILABLE`/`PARTIAL`, 0점 처리 금지(§5) |
| 시주 경계 근접 | **없음** (경계 5분 전 입력도 `CONFIRMED`) | `manse-v2`: 입력 ±15분 안에서 시주가 바뀌면 `PARTIAL` + `HOUR_BOUNDARY_NEAR` + 대안 명식 |

디렉터리는 제안대로 `domain/compatibility/` 패키지를 신설한다. 기존 `domain/timing.py`는 이미 개인·커플 공용이므로 `domain/timing/` 패키지(`individual.py`, `overlap.py`)로 옮기며 동작은 유지한다.

## 4. compat-score-v1 룰 테이블

총점: **C = 0.20·D + 0.35·P + 0.30·E + 0.15·W** (각 영역 0~100, 최종 반올림 정수)

수치는 명리학계 표준이 아니라 Fateweave의 초기 설계 가설이다. 실제 관계 결과로 보정(calibration)된 값이 아니다.

### 4.1 D — 일간 관계 (가중치 20)

두 일간 사이의 관계 하나를 우선순위로 고른다 (중복 집계 없음).

| 우선순위 | 관계 | 기본점 | 비고 |
|---|---|---|---|
| 1 | 천간합 (甲己·乙庚·丙辛·丁壬·戊癸) | 90 | 합이 성립하면 극 관계는 집계하지 않음 |
| 2 | 천간충 (甲庚·乙辛·丙壬·丁癸) | 25 | 戊己 충은 쓰지 않음 (rules 테이블과 동일 가정) |
| 3 | 상생 (어느 방향이든) | 75 | 방향(A→B / B→A)은 기록만, v1 가감 없음 |
| 4 | 비화 (같은 오행) | 60 | |
| 5 | 상극 (충이 아닌 극) | 40 | 방향 기록 |

배우자성 상호성 가산 (같은 영역 안, 상한 100):
- 상대 일간이 내 배우자성(남명 정재·편재, 여명 정관·편관)이면 **+10**, 양쪽 모두면 +20.
- 상대 일지 본기가 내 배우자성이면 +5 (사람당 1회).

### 4.2 P — 배우자궁(일지) 관계 (가중치 35)

기준점 **60** (관계 없음 = 중립). 두 일지 사이에 성립하는 **모든 관계 Fact를 보존**하고, 점수는 아래 규칙으로 계산한다.

| 관계 | 가감 |
|---|---|
| 육합 | +25 |
| 삼합 같은 그룹 (반합 이상, 같은 지지 제외) | +15 |
| 같은 지지 (복음) | 0, 단 자형(辰辰·午午·酉酉·亥亥)이면 형 규칙 적용 |
| 충 | −35 |
| 형 (상형·자형) | −20 |
| 원진 | −20 |
| 해 | −15 |
| 귀문 | −10 |
| 파 | −10 |

**중복 방지 규칙:** 같은 부호끼리는 **가장 큰 것 하나만** 적용하고, 양수 최대값과 음수 최대값을 합산한다.
- 예: 巳申은 육합(+25)과 파(−10)가 동시에 성립 → 60 + 25 − 10 = **75**
- 예: 子未는 해(−15)와 원진(−20)이 동시에 성립 → 음수 중 최대 −20만 적용 → **40**
- 결과는 0~100으로 자른다.

### 4.3 E — 오행 상호보완 (가중치 30, 방향 분리)

보완성을 **B→A**(B가 A에게)와 **A→B**로 따로 계산한다.

사람 X의 필요 오행 `need(X)`:
- 표면 8글자(시주 미상이면 6글자)에서 **0개인 오행**
- **조후 필요 오행** (여름생 수, 겨울생 화 — rules의 JOHU evidence. 궁통보감 표 도입 시 교체)
- 억부 용신 후보는 v1에서 **사용하지 않는다** (학파 차이가 커서 초기 가중치 0)

사람 X의 과다 오행 `excess(X)`: 표면 글자 중 3개 이상인 오행

B→A 점수:
- `need(A)`가 비어 있으면 **70** (보완할 것이 뚜렷하지 않음 = 중립)
- 아니면 `50 + 50 × (B 표면에 1개 이상 있는 need(A) 수 / need(A) 수)`
- `excess(A)` 오행을 B가 표면에 3개 이상 갖고 있으면 **−15** (과다를 더함)
- 0~100으로 자름

**E = (B→A + A→B) / 2 − 비대칭 감점**
- 비대칭 감점: 두 방향 차이가 30 이상이면 −10
- 두 방향 점수와 차이를 모두 근거에 남긴다

일간끼리의 상생은 D에서만 평가하고, E는 표면 분포만 보므로 같은 관계를 중복 가산하지 않는다.

### 4.4 W — 전체 명식 조화 (가중치 15)

기준점 **60**. 교차 기둥 관계(`COUPLE_CROSS_PILLARS`) 중 **일간–일간, 일지–일지는 제외**한다 (D·P에서 평가).

| 관계 (교차) | 건당 가감 |
|---|---|
| 천간합, 지지 육합·삼합 | +5 |
| 충 | −6 |
| 형, 원진 | −4 |
| 해, 파, 귀문 | −2 |

- 같은 기둥 쌍에 여러 관계가 있으면 P와 같은 부호별 최대값 규칙을 적용한다.
- 값이 같은 교차 쌍(예: 두 사람 모두 같은 연주·월주라서 A연·B월과 A월·B연이 같은 관계)은 커플 근거에서 하나의 사실로 합쳐지므로 **한 번만** 센다.
- 가산 합계 상한 +30, 감산 합계 하한 −30.
- 연지–연지(띠) 관계도 이 영역에 포함한다. 띠 비중을 크게 두지 않는다는 조사 결론에 따라 별도 영역으로 두지 않는다.

### 4.5 신살·용신

- 신살(도화·홍염·원진살 등)은 v1 점수에 **넣지 않는다.** 근거와 해석(Claude)에만 쓴다.
- 억부 용신은 v1 점수에 넣지 않는다. 조후 필요 오행만 E에 쓴다.
- 이후 정책(`compat-score-v2` 등)에서 추가할 때는 새 버전으로 만든다.

| 상황 | D | P | E | W | 총점 |
|---|---|---|---|---|---|
| 한쪽 시주 미상 | 계산 | 계산 | 6글자로 계산, `reduced_scope` 표시 | 시주 관련 쌍 제외하고 계산, `reduced_scope` | 계산, 상태 `PARTIAL` |

## 6. 결혼 시기 엔진 (궁합과 별도 시간축)

### 6.1 개인 연도 신호 점수 (timing-score-v1)

기존 `timing.signals()`의 단서에 가중치를 둔다.

| 분류 | 단서 | 점수 |
|---|---|---|
| 핵심 | 배우자성 천간, 배우자성 지지, 일간 합, 배우자궁 육합, 배우자궁 삼합 | 각 +2 |
| 보조 | 배우자궁과 같은 십성, 도화, 홍염, 대운 배우자성, 대운-배우자궁 합, 억부 희용 오행 | 각 +1 |
| 주의 | 배우자궁 충 | −2 |
| 주의 | 배우자궁 형·원진, 경쟁·견제 십성 | 각 −1 |

- `year_signal = 핵심 + 보조 + 주의` (정수, 확률 아님)
- 세운 지지가 그해 대운 지지와 충이면 주의 −1, 합이면 보조 +1 (신규 단서 `SEWOON_DAEWOON_CHUNG`/`_HAP`)

### 6.2 공통 유리 시기 (overlap)

- **후보 조건:** 그해 A와 B 모두 핵심 단서가 1개 이상이고, 어느 쪽에도 배우자궁 충이 없을 것
- **정렬:** `min(A의 신호 점수, B의 신호 점수)` 내림차순 → 동점이면 두 점수 합 → 연도. 평균을 쓰지 않는다 (한쪽만 강한 해가 위로 올라오는 것을 막기 위해)
- **후보가 없으면** `candidates = []`와 사유를 반환한다. 억지로 한 해를 고르지 않는다.
- 후보에서 빠진 해도 연도별 기록(양쪽 단서·주의)은 그대로 남긴다.

### 6.3 나이대 전체 요약

향후 N년과 별도로, 각자 20~50세 구간을 대운별로 나눠 신호 점수 상위 3개 연도를 요약한다 (`LIFE_TIMING`). 커플은 두 사람 나이가 모두 20~50세인 연도에 같은 overlap 규칙을 적용한다.

## 8. 검증 규칙 추가 (finalize_report)

- 리포트가 궁합 지수를 언급하면, `COMPAT_SCORE`를 인용한 computed claim이 있어야 하고 `computed_values.score`가 서버 값과 같아야 한다.
- 본문에서 "궁합 (지수|점수) N점" 형태의 숫자는 서버의 총점 또는 영역 점수 중 하나와 같아야 한다 (`SCORE_MISMATCH`).
- 공통 유리 시기로 제시한 연도는 `TIMING_OVERLAP.candidates` 안에 있어야 한다. 후보가 없는데 "최적의 해"를 단정하면 거절한다.
- "결혼 확률", "성사 확률", "N% 확률" 표현은 기존대로 거절한다.

## 9. 함께 진행하는 정확도 작업 (A·D)

- **manse-v2 시주 경계:** 입력 ±15분 안에서 시주가 바뀌면 `PARTIAL` + `HOUR_BOUNDARY_NEAR`(경계까지 남은 분) + 대안 명식.
- **신강약 2개 관법:** 라이브러리 10점제 + 통근(지장간 본기 1.0·중기 0.6·여기 0.3)·월령(왕상휴수사) 반영 점수. 판정이 갈리면 `STRENGTH_DIVERGENT`. 종격 판정(korean-saju `OegyeokAnalyzer`)을 evidence로 내고, 정격이면 종격 해석을 금지한다.
- **기준 케이스:** 조사 보고서의 가상 사례 3건(2026-08-01 10:30 / 10-11 14:00 / 12-09 18:30, 서울)을 고정 테스트로 추가한다. 현재 엔진과 네 기둥이 모두 일치함을 확인했다. 추가로 `lunar-python`과 무작위 날짜 교차 검증을 개발용 테스트로 둔다.
